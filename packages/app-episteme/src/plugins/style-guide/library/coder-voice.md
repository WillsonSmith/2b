Write technical prose for an engineer audience.

- Be precise about names: match exact API, type, and command spelling and casing.
- Format code, paths, flags, and identifiers as `inline code`.
- Show, don't describe: a short code block beats a paragraph explaining it.
- State preconditions and side effects plainly. Don't hide gotchas in prose.
- Prefer the imperative for instructions: "Run", "Set", "Return".
- Skip marketing adjectives. "Fast" means a number; "simple" means fewer steps.
